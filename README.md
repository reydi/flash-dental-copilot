# Flash Dental Copilot — v1

A small, inspectable API that answers plain-language questions over a messy
after-sales operation's documents, and **abstains when it isn't sure**. It's the
working core of the "Operations to Boardroom" case study — the v1 *shape* of a
grounded copilot for [Flash Dental](https://flashdental.id)'s field-service data.

> **This is the v1 shape, not the full platform.** Retrieval here is a transparent
> TF-IDF + cosine model so the whole thing runs anywhere with no keys and no cloud.
> Exactly one function — `embed_text_as_tfidf_vector` — is the seam where production
> swaps in Vertex AI embeddings to match by *meaning* instead of by word. Everything
> else (grounding, abstaining, PII redaction, computed KPIs) is unchanged in prod.

## What it does

Each answer runs the same path — the request-path from the deck, in code:

```
question ─▶ retrieve (rank documents) ─▶ ground (cite the top match)
             ─▶ abstain if the best match is too weak ("not in our records")
             ─▶ de-identify PII at the boundary
             ─▶ attach a KPI computed by code (never generated by the model)
```

Two design commitments the deck argues, enforced here:

- **It refuses rather than invents.** Below a similarity threshold the copilot
  abstains — a wrong answer would destroy the trust the cockpit depends on.
- **KPIs are computed, never generated.** First-time-fix, cycle time, and warranty
  dates come from `kpi_computation.py`; the model only ever explains a number.

## Quickstart

```bash
make install          # create .venv and install dependencies
make generate         # (re)build the demo corpus into flash_dental_copilot/data/
make test             # run the test suite
make run              # serve on http://localhost:8080
```

Ask it something:

```bash
curl -s -X POST localhost:8080/ask \
  -H 'content-type: application/json' \
  -d '{"domain":"assets","question":"asset FD-1042 keeps failing — show its service history"}'
```

```jsonc
{
  "abstained": false,
  "similarity_score": 0.408,
  "answer_text": "Dental unit FD-1042 (model DC-300) service 2025-01: suction motor failure recurred ...",
  "citation_document_id": "service_log_FD-1042_2025-01",
  "kpi_summary": "first-time-fix 78.8% · FD-1042 warranty → 2025-06-15 · 7 outstanding jobs",
  "pii_masking_example": "Report: [PERSON_1] serviced serial [SERIAL_1]; contact [PHONE_1].",
  "computed_by_code_note": "KPIs computed by code, not generated by the model."
}
```

Ask it something out of scope (`"what is the wifi password"`) and it abstains.

## Endpoints

| Method | Path                            | Purpose                                   |
| ------ | ------------------------------- | ----------------------------------------- |
| GET    | `/health`                       | Liveness probe                            |
| GET    | `/domains`                      | Domains it can answer over                |
| GET    | `/domains/{domain}/presets`     | Example questions for a domain            |
| POST   | `/ask`                          | Retrieve → ground → abstain → mask → KPI  |

Domains: `assets` (the machines) and `technicians` (the people who service them).

## Layout

Each file has one responsibility and stays under 200 lines; the core is pure
(no I/O), with framework and disk pushed to the edges.

```
flash_dental_copilot/
  retrieval.py        # pure TF-IDF + cosine ranking   ← the Vertex seam
  grounding.py        # abstain gate + answer assembly
  pii_redaction.py    # de-identify names, serials, phones (Cloud DLP in prod)
  kpi_computation.py  # deterministic KPI math
  corpus.py           # load + index documents (I/O edge)
  service_records.py  # load tickets, summarise KPIs (I/O edge)
  schemas.py          # request/response models
  api.py              # FastAPI edge: wires the core to HTTP
  data/               # generated corpus + tickets (committed)
scripts/
  corpus_entities.py  # declarative Flash Dental entities
  generate_corpus.py  # expand entities → a larger, realistic corpus
tests/                # unit tests per module + end-to-end API tests
```

## Deploy to Cloud Run

```bash
gcloud run deploy flash-dental-copilot \
  --source . \
  --region asia-southeast2 \
  --allow-unauthenticated
```

`asia-southeast2` is Jakarta — the same data-residency region the deck argues for.
Cloud Run injects `$PORT`; the container already reads it.

## The production path

The demo matches *words*, so it can trip on "goal" vs "goals". That gap is the
cleanest argument for the real thing: swap `embed_text_as_tfidf_vector` for a
Vertex AI text-embedding call and retrieval matches by meaning — the rest of the
pipeline is untouched. Same for the boundaries: `pii_redaction` becomes Cloud DLP,
`corpus`/`service_records` read from BigQuery instead of JSON. The *shape* is the point.

Part of the [Operations to Boardroom](https://main.ops-to-boardroom.pages.dev) case study.
